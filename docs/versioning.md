# 版本、改写与可比性

初始发布为 `v1.0.0`，结果格式为 `1.1`。Skill、提示词、提取器和研究协议各自为 `1.0.0`，没有因为相同数字就视为同一件事。

| 标识 | 解释 | 谁改变它 |
| --- | --- | --- |
| `schema_version` | JSON 字段、类型和允许取值 | 格式维护者 |
| `provenance.protocol_version` | 窗口、指标含义、研究/公开约定 | 方法维护者 |
| `provenance.prompt_version` | 实际使用的固定提示词；没有用则 `not_used` | 参与者声明 |
| `provenance.extractor_version` | 生成指标的固定脚本；手动填写则 `not_used` | 脚本自动写入或遗留未知 |
| `provenance.skill_version` | 使用的本机 Skill 版本；未使用则 `not_used` | Skill 显式传入的来源声明 |
| 发布标签与 `versions.json` | 一次发布包含的组件和文件指纹 | 发布维护者 |

发布标签可查到对应 Git 提交，清单指纹可核对文件字节；不会把 Git 提交散列误当运行证明。每份提交本机预览全部研究字段及上述来源信息，发送的字段名称由对应 schema 固定。

旧格式 `1.0` 没有版本来源字段。网站仍接受它，但升级结果外壳时只能标为协议 `legacy-1.0`，提示词/提取器/Skill `unknown`，不能补写为后来发布的版本。历史数据库不会被静默改写。

Fork 内容可以自由修改。修改内容须采用自己的版本标识，不能沿用官方发布版本假称未修改。第一版网站只允许已登记的版本、`not_used` 和 `unknown`，未知实验可提交方法 PR 申请登记；登记须检查字段与隐私兼容，不自动接收任意字符串。

不要盲目混合不同版本。文字澄清、字段变化和统计规则变化的影响不同：维护者发布说明中给出可比性判断；不能确认则按版本分组并保留未知。提高版本号本身不会消除选择偏差、缺失或混杂。
